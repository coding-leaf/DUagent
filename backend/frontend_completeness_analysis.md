# 前端完整性与可用性深度评估报告

本报告针对以下前提进行分析：**“假设去除 Mock、且后端数据接口完全正确且对齐，当前前端代码是否算是一个‘完整’的前端系统？”**

---

## 一、 评估结论：是否为完整的前端？

**结论：不算完整。当前前端本质上是一个“高保真视觉交互原型（High-Fidelity Prototype）”，而非生产就绪的完整前端应用。**

即使我们假设后端接口完美无缺，当前前端代码中依然存在大量 **硬编码数据（Hardcoded Data）、静态占位符（Static Placeholders）、未实现的交互逻辑**，以及**核心功能缺失**（如代码演练沙盒、流式传输解析和动态图表绘制）。

如果直接连上正确的数据接口，虽然部分表单和列表可以动态渲染，但页面上很大一部分数据、图表、甚至部分按钮跳转依然是“静态假数据”，无法反映真实的学生学情。

---

## 二、 关键页面的“不完整性”与硬编码清单

### 1. 资源阅读详情页 (`ResourceDetail.jsx`) — 纯静态占位
本页面目前是一个完全硬编码的“演示文档”，不具备动态渲染任意资源的能力：
* **内容硬编码：** 页面上的正文《深入理解 AVL 树：平衡二叉搜索树...》、图解及解释全部是写死在 JSX 中的静态文本，**没有从后端读取任何课件正文的 API 绑定**。
* **学习指标硬编码：**
  * 左侧进度条写死为 `65%`，已读字数比例也是静态的。
  * 阅读时间写死为 `12m`，建议用时写死为 `25m`。
  * 核心关键词写死为：`二叉平衡树`、`AVL旋转`、`递归遍历`。
* **路径连线图硬编码：** 右下角展示的学习路径节点全部是写死在 HTML 里的静态节点。

---

### 2. 在线测试与答题页 (`Quiz.jsx`) — 核心交互缺失
* **倒计时器静态化：** 顶部的计时器 `18:45` 是一个写死的文本字符串，**没有实现任何 JS 定时器递减逻辑**，时间不会流动。
* **题型硬编码：** 题目左上角的题型标签写死为 `[单选题]`，不具备适配多选、代码、简答等多种题型的动态标签渲染逻辑。
* **示意图区域占位：** “节点索引关系示意图区域”是一个由虚线框和静态 `account_tree` 图标组成的占位卡片，**无法根据题目数据动态绘制对应的树形/图形拓扑图**。

---

### 3. 学习路径规划页 (`LearningPath.jsx`) — 局部静态推荐
虽然页面中央的闯关节点连线能根据后端返回 of `learningPath.nodes` 数组进行渲染，但卡片内外的很多核心数据依然是写死的：
* **阶段欠缺知识点硬编码：** 阶段1已完成卡片中，欠缺知识点写死为 `尾递归优化`。
* **底部推荐板块完全静态：**
  * 导图推荐卡片写死为：非线性结构全景图。
  * 讲义推荐卡片写死为：`AVL树：旋转的艺术.pdf`。
  * 混合练习集写死为：中阶数据结构挑战赛。
  以上推荐卡片均**没有调用后端的推荐算法接口**，无法做到因人而异。

---

### 4. 学习效果展示页 (`LearningEffects.jsx`) — 数据图表硬编码
* **表格数据硬编码：** 页面中轴的“学习路径进度表”中，三行数据（线性表与栈、散列表、红黑树进阶）的状态、平均耗时、掌握评分等全部是写死在 `<tbody>` 里的静态 HTML，**没有与后端返回的 `progress_table` 等数据表发生任何绑定**。
* **资源反馈圆环图硬编码：** 页面饼图的百分比数据（动态演示 60%、代码调试 25%）和 SVG 扇区的 `strokeDasharray` 弧度控制是**写死的静态数值**，无法根据学生真实的交互行为比例发生偏转。

---

### 5. 教师学生详情报告 (`TeacherStudentReport.jsx`) — 图表视觉伪装
* **柱状图高度硬编码：** 页面中央的“认知成长曲线”由 12 根柱子组成，其高度在 Tailwind 类名中写死的（如 `h-[40%]`、`h-[55%]`、`h-[95%]`），**没有将后端返回的 `cognitive_growth` 数据动态转换为 CSS 高度样式**。
* **资源反馈图硬编码：** 环形图百分比与扇区比例全部写死。

---

### 6. AI 问答聊天室 (`AIChat.jsx`) — 附件与多模态占位
* **文件上传为假按钮：** 输入框左侧的 `attach_file` 图标按钮点击无上传或文件选择逻辑。
* **语音录入为假按钮：** 语音录入图标无实质功能。
* **树形示意图硬编码：** AI 在答疑中输出的树形拓扑图是硬编码画出的。
* **SSE 协议缺失：** 未实现 text/event-stream 流式打字机打字效果。

---

## 三、 产品规划建议：阶段一与后续开发界限 (Feature Gaps)

为了在阶段一中防止开发范围无限扩大（Scope Creep），必须将**对齐现有接口**和**后续产品能力增强**做出严格区分。

### 📌 阶段一：当前契约对齐范围 (本期核心)
* 移除 Mock 拦截，使网络请求走真实后端。
* 前端通过 `GET /users/me` 与 `/courses` 接口跑通基本鉴权与路由拦截逻辑。
* 修复 ESLint 编译报错，适配后端现有接口中存在的表格式数据或字段简表（在雷达图中将后端返回的 `modal_preference` 作为原始数据输入）。
* **隐藏或禁用**无正式接口支撑的产品卡片及按钮。

### 🚀 阶段二 / 后续产品能力 (需单独确认，不包含在阶段一中)
以下建议属于产品层面的能力升级或核心特性补齐，**在阶段一内不做开发要求，后续需单独向用户确认**：
1. **资源正文动态解析渲染：** 在 `ResourceDetail.jsx` 中编写富文本/Markdown 解析引擎，对齐资源内容拉取。**这不仅需要前端 Markdown 渲染器，还需要新增资源详情读取接口契约（即扩展 Client API 与可能的 SQL 数据库表结构，包含 content 存储）**。
2. **代码实操沙盒 (Monaco Editor)：** 在 `Quiz.jsx` 或独立组件中引入真正的代码编辑器（如 Monaco Editor / CodeMirror），替代现有的答题题型重定向。
3. **多模态图表库集成 (Recharts)：** 引入 `Recharts` 等第三方库替换手写的原生 SVG，实现模态偏好和月度成长曲线的自适应动态绑定。
4. **附件与音频处理逻辑：** 真正实现聊天室文件上传和语音转文字服务接口的对接。
