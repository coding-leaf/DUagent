# A3 赛题需求差距审计

> 日期：2026-06-26  
> 范围：根目录 `赛题疑点` 摘录、当前前端页面、Backend API、Agent Service 能力与近期工作记录。  
> 定位：本审计用于比赛优先阶段的开发排序，不替代 API 契约文档。

## 一、总体判断

当前系统已经具备个性化智能学习系统的主体能力：学生画像、学习路径、课程资源、练习、AI 答疑、学习效果评估、个性化资源生成均有前端页面和后端接口支撑；Agent Service 也已有 profile、learning path、resources、assessment、evaluation、tutoring 等能力。

主要差距不在三端角色划分，而在比赛验收表达、AIChat Agent 化程度和若干硬指标缺口：

- 学生端能力分散在多个页面，AIChat 还没有成为可调用工具、可跳转页面、可触发学习动作、可展示审查过程的 Agent 工作台。
- 课程级资源类型当前正式口径仍以 `document`、`mindmap`、`reading`、`code` 四类为主，未满足赛题“至少 5 种类型”的硬要求。
- 多智能体协同、防幻觉审核、生成进度等能力更多存在于 Agent 内部、任务状态或日志中，后端和 Agent 日志也尚未完整覆盖 tool 调用、审查、fallback 与来源摘要。
- 个性化推荐理由还不够显式，未稳定展示“画像维度 / 薄弱点 / 学习进度”与资源推荐之间的对应关系。
- Agent 缺少稳定的 user memory / content 附属接口，长期记忆、内容产物和工具调用状态还没有形成统一能力边界。
- 完整课程知识库和提交材料后续需要整理，但当前只作为轻量收口项，不作为下一阶段开发主线。

建议后续主线定位为：

```text
管理员端：课程知识库与系统运维输入层
教师端：学情观察与教学辅助展示层
学生端：依靠 Agents 的个性化智能学习系统主体
Agent Service：画像、路径、资源、答疑、评估、防幻觉与生成编排核心
```

## 二、三端功能定位审计

### 2.1 学生端

**当前实现依据：**

- 路由：`frontend/src/App.jsx`
- 页面：`Dashboard`、`StudentProfile`、`LearningPath`、`Quiz`、`PracticeResult`、`AIChat`、`LearningEffects`、`PersonalizedResources`
- 主要接口：`/profile`、`/profile/refresh`、`/learning-path`、`/learning-path/refresh`、`/learning-path/nodes/{node_id}/resources`、`/quiz/questions`、`/quiz/submit`、`/tutoring/chat`、`/evaluation`、`/evaluation/refresh`、`/personalized-resources`

**状态：部分满足。**

学生端是功能主体，但当前像一组并列模块：资源库、画像、路径、练习、答疑、学习效果、个性化资源分别存在。下一阶段不优先新增独立学习中心，而是将 AIChat 改造成 Agent 个性化学习工作台：通过对话触发工具调用、展示过程、跳转页面或执行自动学习动作。

**建议：**

- 优先改造 `AIChat` 为三栏 Agent 工作台：左侧对话记录，中间 Agent 工作区 / 内容展示区，右侧 AI 对话区。
- 展示 tool 调用、审查结果、来源摘要、fallback 状态和可执行动作。
- 中间工作区承载 Agent 产物：学习路径片段、推荐资源、薄弱点分析、练习题预览、HTML 类 PPT、代码实操任务、学习计划、审查报告等。
- 首批工具以学习状态查询和轻量内容草稿为主：查画像、查学习路径、查薄弱点、查推荐资源、查学习效果，并能生成学习计划、题目预览、HTML 类讲解页等。
- 后续再接入更重的学习动作触发和内容生成：生成个性化题目、刷新画像/路径/评估、保存为学习资源、实时问题、项目任务等。
- 保留现有页面作为详情页，不推倒重做。

### 2.2 教师端

**当前实现依据：**

- 页面：`TeacherConsole`、`TeacherStudentReport`
- 主要接口：`/courses`、`/teaching/classes/{class_id}/students`、`/teaching/classes/{class_id}/insights`、`/teaching/classes/{class_id}/students/{student_id}/learning`
- 后端服务：`TeachingService`、`StudentReportQuery`、`ClassInsightsQuery`

**状态：满足辅助端定位。**

教师端主要查看班级、课程资源、学生列表、班级洞察、学生画像、薄弱点、练习统计、路径进度和近期活动。它没有直接替学生决定学习路径，也没有成为个性化生成的控制中心，因此不构成明显重心漂移。

**建议：**

- 比赛叙事中将教师端定义为“学情观察与系统成果展示端”。
- 避免继续扩展教师端主动干预学生学习路径或资源推送的能力，除非后续明确作为教学辅助加分项。
- 教师端近期保持现状，最多优化现有展示体验和数据可读性。

### 2.3 管理员端

**当前实现依据：**

- 页面：`AdminConsole`、`CatalogManagementPanel`、`CourseCatalogDrawer`
- 主要接口：`/admin/users`、`/admin/registration-codes`、`/admin/logs/*`、`/admin/course-catalogs`、`/admin/course-catalogs/{catalog_id}/materials/upload`、`/admin/course-catalogs/{catalog_id}/ingestions`、`/admin/course-catalogs/{catalog_id}/knowledge-graphs/generations`、`/admin/course-catalogs/{catalog_id}/resources/generations`、`/admin/course-catalogs/{catalog_id}/quiz/generations`

**状态：满足输入层定位，但有叙事抢主线风险。**

管理员端承担课程资源库、资料上传、知识入库、知识图谱、课程级资源和题库生成，这些能力很重。它们是赛题要求中“至少一门完整高校课程知识库”的必要支撑，但如果比赛表达从管理员端开始，系统容易被理解成资源管理平台。

**建议：**

- 管理员端在比赛材料中定位为“课程知识库准备与系统运维入口”。
- 管理员端后续以合并部分功能、优化 UI 和减少操作分散为主。
- 后续重点不应继续堆管理员端能力，而应把管理员端产物反哺到 AIChat Agent 工作台和学生端学习闭环。

## 三、赛题必选功能差距

### 3.1 对话式学习画像自主构建

**赛题要求：**

通过自然语言对话，结合专业、学习目标、学习历史等自动抽取特征，构建不少于 6 个维度的动态学生画像，并支持随学随新。

**当前实现依据：**

- 前端：`StudentProfile`
- Backend：`/profile`、`/profile/initialize`、`/profile/dialogue-update`、`/profile/refresh`、`/profile/learning-goal`、`/profile/custom-instruction`
- Agent Service：`profile`、`memory` 相关能力

**状态：部分满足。**

系统已有画像展示、刷新、学习目标、个性化偏好、对话更新接口；画像维度已覆盖模态偏好、引导粒度、知识坐标、认知盲区、学习动机、学习习惯等方向。但前端主流程中“通过自然语言对话构建画像”的入口不够突出，画像与 AI Chat 的关系也不够显式。

**建议：**

- 在学生端主入口加入“告诉 Agent 我的目标 / 画像更新”入口，调用现有 `/profile/dialogue-update` 或复用 AIChat 后的画像刷新。
- 明确展示 6+ 维画像来源：问卷、对话、练习、资源使用、学习活动、评估结果。

### 3.2 多智能体协同资源生成，至少 5 类资源

**赛题要求：**

体现多智能体架构，不同角色智能体协作完成至少 5 种类型个性化资源生成，如课程讲解文档、思维导图、练习题、拓展阅读、多模态视频/动画、代码实操案例、实践项目材料等。

**当前实现依据：**

- 前端：管理员端课程级资源生成、学生端 `PersonalizedResources`
- Backend：`/admin/course-catalogs/{catalog_id}/resources/generations`、`/personalized-resources/generate`、`/quiz/generate`
- Agent Service：`resources_workflow`、`resources_agents`、`resources_critic`、`assessment`
- 当前正式资源类型：`document`、`mindmap`、`reading`、`code`

**状态：部分满足，存在硬缺口。**

系统已有多 Agent 资源 workflow、Planner、ResourceAgent、Critic、Aggregator 等内部能力，也有题目生成能力。但当前资源类型正式口径仍是四类；题库能力在 quiz 链路中存在，但未稳定纳入“5 类资源生成”的产品和文档口径。

**建议：**

- 优先补齐第 5 类资源。推荐选择 `project` / `practice_project`，对应“实践项目学习材料”，比视频生成更稳。
- 将题库/个性化练习明确纳入资源体系展示，或将其作为独立第 5 类能力在比赛材料中解释清楚。
- 在学生端展示资源由哪些 Agent 生成、是否经过 Critic 审核、是否使用 fallback。

### 3.3 个性化学习路径规划和资源推送

**赛题要求：**

结合画像、专业、学习进度、知识掌握情况和偏好，规划动态学习路径，并基于画像实现资源精准推送。

**当前实现依据：**

- 前端：`LearningPath`、`NodeResourcePanel`、`PersonalizedResources`、`LearningEffects`
- Backend：`/learning-path`、`/learning-path/refresh`、`/learning-path/nodes/{node_id}/resources`、`/personalized-resources`
- Agent Service：`learning_path`

**状态：部分满足。**

学习路径、节点资源、个性化资源和学习效果评估均已存在。路径节点包含状态、mastery、reason 等字段；资源可按节点关联。但当前路径更接近基于课程知识图谱的排序和状态展示，距离“综合画像、长期记忆、薄弱点、目标和可用时间生成个性化学习路径推荐”还有差距。资源推荐理由也不够产品化，用户难以一眼看出推荐资源和画像维度、薄弱点、学习进度之间的关系。

**建议：**

- 在 AIChat 工作区或资源卡片展示推荐依据：薄弱知识点、路径当前位置、画像偏好、练习错误率。
- 后续补充真正的个性化学习路径推荐：支持补弱优先、项目实践优先、考试冲刺优先等候选策略，并说明每条路径的依据和预期收益。
- 本次只补充需求和设计方向，不实现路径推荐算法。
- 后端可优先复用现有数据计算推荐理由，暂不急于扩展复杂推荐模型。

## 四、可选加分项差距

### 4.1 智能辅导

**赛题要求：**

学生遇到问题时提供即时、多模态、针对性的答疑服务。

**当前实现依据：**

- 前端：`AIChat`
- Backend：`/tutoring/chat`、`/tutoring/conversations`
- Agent Service：`tutoring`、`tutoring_react`、`tutoring_response_critic`、RAG 检索

**状态：基本满足文字答疑，Agent 工作台能力不足。**

系统已有 AI Chat、课程 scope、历史会话、RAG 和 critic 审查基础，但当前 AIChat 疑似存在非流式输出问题，tool 调用展示、审查展示、页面跳转和自动动作触发能力不足。多模态呈现目前更多是 Markdown、知识点、建议和资源侧边栏，尚未达到“短视频讲解”等更强多模态能力。

**建议：**

- 优先修复或确认 AIChat 流式输出链路，并让 tool 调用可见。
- 比赛初期将智能辅导定位为文字 + Markdown + 知识点引用 + 相关资源推荐 + 可执行动作。
- 视频资源后续考虑通过爬虫、自建链接视频库或外部视频库实现，不作为近期硬切口。
- 近期更现实的内容扩展是 HTML 类 PPT、实时问题生成、个性化讲解材料和项目/实操任务。

### 4.2 学习效果评估

**赛题要求：**

跟踪学习行为、练习测试、资源使用反馈，动态评估学习效果并调整资源推送和学习计划。

**当前实现依据：**

- 前端：`LearningEffects`、`PracticeResult`
- Backend：`/evaluation`、`/evaluation/refresh`、`/learning-activities`、`/quiz/history`
- Agent Service：`evaluation`

**状态：部分满足。**

系统已有学习效果页面、节点掌握情况、练习记录、评估刷新和学习活动记录。动态调整路径和资源推送已有基础，但前端闭环表达不足：评估结果如何导致下一步资源推荐或路径更新，目前不够直观。

**建议：**

- 在学习效果页或学习中心加入“根据本次评估调整路径 / 生成个性化资源”的明确入口。
- 将错题触发个性化资源生成作为动态优化闭环的核心证据。

## 五、非功能需求差距

### 5.1 界面与 AI 产品交互

**状态：部分满足。**

系统已有 AI Chat、Markdown 渲染、资源卡片、学习路径可视化、画像卡片和任务状态。缺口是 AIChat 还没有成为统一的 Agent 工作台，导致比赛评审需要在多个页面之间理解系统价值，也难以看见 Agent 如何调用工具、审查内容和推动学习动作。

**建议：**

- 优先改造 AIChat，而不是大范围重做学生端 UI 或新增独立主页。

### 5.2 防幻觉与内容安全

**状态：部分满足。**

Agent Service 已有 resource critic、tutoring response critic、assessment quality gate、learning path 节点白名单等机制，具备防幻觉基础。但这些结果主要存在于内部判断、日志或 fallback 字段中，后端/Agent 日志也未完整形成可查询、可展示的审查证据。

**建议：**

- 在 AIChat tool 调用卡片、资源详情或生成任务卡片展示：来源依据、审核状态、可信度、fallback 原因。
- 后端和 Agent 日志需要记录 tool 调用、输入输出摘要、审查结果、fallback、来源命中摘要。
- 先产品化已有 critic 结果，不急于引入新安全框架。

### 5.3 响应时间与进度追踪

**状态：部分满足。**

系统已有异步任务、`/tasks/{task_id}` 轮询、生成中状态、刷新中状态和 SSE 聊天基础。缺口是 AIChat 流式体验需要复核，多 Agent / tool 执行过程没有按角色展示，用户只能看到最终文本或“处理中”。

**建议：**

- 在 AIChat 中优先展示工具调用阶段，再逐步扩展到资源生成任务中的 Planner、ResourceAgent、Critic、Aggregator 阶段状态。
- 若接口暂不扩展，可先用任务状态和日志摘要做最小展示。

## 六、提交物要求差距

### 6.1 完整高校课程知识库

**状态：部分满足。**

管理员端已有课程资源库、资料上传、知识入库、知识图谱生成等能力。但比赛提交需要整理成明确交付包：原始资料、KG、导入说明、模型配置、运行步骤、示例账号和演示数据。

**建议：**

- 整理一门完整课程知识库交付包，建议选“数据结构”或当前系统已有课程。
- 文档说明资料来源、结构、导入方式、Qdrant/数据库依赖、可复现实验步骤。

### 6.2 演示 PPT、视频、AI Coding 说明

**状态：未纳入本轮代码实现。**

当前仓库更偏源码和接口文档，尚未看到专门的比赛提交材料目录。该项短期只需轻量标注，不作为近期开发主线。

**建议：**

- 后续新增 `docs/competition/` 或等价目录，存放演示脚本、PPT 大纲、视频脚本、AI Coding 使用说明。

## 七、优先级建议

### P0：比赛硬指标

1. AIChat Agent 工作台 v1：左侧对话记录，中间展示 Agent 产物，右侧 AI 对话；展示 tool 调用、审查结果、来源摘要、fallback 状态，并支持跳转画像、路径、资源、练习和学习效果页面。
2. 后端与 Agent 日志补全：记录 tool 调用、输入输出摘要、审查结果、fallback、来源命中摘要。
3. user memory / content 附属能力：补齐 Agent 所需长期记忆、内容产物和工具调用上下文边界。
4. 补齐至少 5 类资源生成口径：优先 `project` / `practice_project` 或将题库正式纳入资源体系。
5. 推荐理由产品化：资源推荐必须说明来自画像维度、薄弱点或路径进度。

### P1：赛题可信度与展示

1. 多 Agent 过程展示：先在 AIChat 展示 tool 调用，再扩展到 Planner、ResourceAgent、Critic、Aggregator 阶段可见。
2. 防幻觉展示：来源引用、审核状态、可信度、fallback 原因。
3. 错题触发个性化资源/练习闭环强化。
4. 个性化学习路径推荐：从写死/静态路径状态展示，演进为基于画像、记忆、薄弱点、目标和可用时间的多策略推荐。

### P2：提交材料

1. 整理完整课程知识库交付包。
2. 准备比赛演示脚本和视频脚本。
3. 整理 AI Coding 使用说明、开源工具/框架说明和协议来源。

## 八、结论

当前系统没有发生严重角色漂移：教师端是观察端，管理员端是输入层，学生端具备学习闭环基础。比赛优先阶段的关键不是推倒三端，而是把学生端升级为清晰的 Agent 个性化学习主入口，并补齐“5 类资源、推荐理由、多 Agent 过程、防幻觉展示、课程知识库交付包”这几个评审可见缺口。
