# Frontend Decisions

本文档记录前端模块跨阶段仍成立的稳定决策。阶段状态和临时执行细节写入 `../WORKFLOW.md` 或 `temporary-implementation.md`。

## 正式契约只看根目录 Client API

- 正式前端接口契约以 `../../docs/10-client-api/*` 为准。
- `frontend/docs/` 下不维护正式 Client API 副本。
- 如果前端页面、历史文档或 Mock 数据与正式契约冲突，不按前端推测扩展接口。

原因：避免同名文档多份复制后产生契约漂移。

## 当前 Client API 不足以承载完整前端目标

当前前端完整页面目标已经超过现有 Client API 规范能够正确承载的范围。现有契约仍是当前正式来源，但不足以覆盖完整页面需要的字段、指标、日志、图表和数据来源。

影响：

- 阶段一只能做现有契约已覆盖的主链路收口。
- 超出能力进入阶段二契约审查。
- 契约审查完成前，不把页面设想直接落成正式开发目标。

## Mock 只用于演示和断网调试

- `VITE_USE_MOCK=true` 只用于本地演示、断网调试和非正式体验检查。
- Mock 数据不能作为正式字段存在性的证据。
- 真实联调默认使用 Backend API。

原因：阶段一目标是验证真实 Backend API 主链路，不能让 Mock 掩盖契约缺口。

## 空数据优先展示 Empty/Unknown

如果 Backend 返回空数组、空对象或空值，前端优先展示 Empty/Unknown 状态。

禁止行为：

- 用静态示例数据替代真实返回。
- 在页面层补造不存在的指标。
- 把历史设计稿中的字段当作真实 API 字段。

原因：空状态能暴露实现或数据来源问题；假数据会隐藏联调风险。

## 页面字段报告是阶段二输入

`../前端页面字段与布局结构数据报告.md` 是页面设想、视觉布局和阶段二契约审查输入，不是当前 Client API 契约，也不是阶段一实现清单。

原因：该报告覆盖完整产品页面能力，其中一部分尚无正式接口、SQL 或 Agent 数据来源支撑。
