# 2026-06-05 Manual Smoke Feedback

## Scope

本文件记录真实前端体验中发现的轻量问题，作为阶段二接口差距分析和后续实施计划的补充输入。

记录原则：

- 仅记录体验现象、初步判断和建议处理方向。
- 不直接替代 `Client-API.openapi.json` 或正式需求文档。
- 实施前仍需逐项核对 OpenAPI、Backend、Agent 和当前页面代码。

## Student Side

| ID | 页面/能力 | 体验反馈 | 初步判断 | 建议处理 |
|---|---|---|---|---|
| MS-01 | 个人信息 / 模态偏好 | 当前模态偏好包含“代码实操”，但用户认为模态偏好应偏向资源生成类型；“代码实操”不应作为该项偏好，或前端应隐藏该项。 | 字段语义和前端展示分类不清。当前 Profile 能力需要重新区分“学习资源类型偏好”和“学习交互方式偏好”。 | P1：阶段二审查 Profile 字段语义；若 OpenAPI/Backend 无明确支撑，前端先隐藏或改为只展示契约内可解释字段。 |
| MS-02 | 个人信息 / L1-L3 引导等级 | L1/L2/L3 当前缺少可交互能力。 | 当前更像静态展示，不满足用户对“可调整学习指导强度”的预期。 | P1：确认是否允许用户修改 guidance level；如允许，需补 Client API/Backend 更新能力或复用现有 profile 更新端点；如不允许，前端应降低为只读说明。 |
| MS-03 | 资源 / 课堂讲义 | “课堂讲义”期望是 AI 根据给定 PPT 生成合适 AI 课件，可包含详细文字讲解。 | 当前资源详情/资源生成能力与页面预期存在差距，涉及上传材料、Agent 生成、资源正文存储和展示。 | P1/P2：纳入阶段二资源详情与资源生成审查；先确认 PPT 输入来源、生成结果结构、异步任务状态和资源正文字段。 |
| MS-04 | 个人信息修改 | 没有个人信息修改界面。 | 阶段一已清理未声明的 `PUT /profile` 前端方法；当前正式契约不支撑完整资料修改。 | P1：如产品需要，需先补 Profile 更新契约；未补契约前不建议前端恢复假编辑入口。 |
| MS-05 | 课程 / 加入课程入口 | 学生端没有看到添加或加入课程的入口。 | `courseService.joinCourse(inviteCode)` 已封装 `POST /courses/join`，但当前页面未暴露入口；更像前端适配缺失，而不是新增后端能力。 | P1：核查 Dashboard/Navbar/课程选择器位置，补一个输入邀请码加入课程的小入口；成功后调用 `refreshCourses` 并切换到新课程。 |
