# 阶段二学生端数据契约审查设计

> 状态：设计稿
> 日期：2026-06-05
> 范围：学生端数据源审查，附带教师端投影依赖标注

## 1. 背景

当前前端主链路已经能在真实 Backend、Agent Service 和测试数据环境下运行，但完整页面目标已经超过现有 Client API 契约承载范围。部分页面仍存在静态设计稿、Mock 分支、默认假值、契约外字段和后端空实现混杂的问题。

本轮任务不直接更新 OpenAPI，也不直接修改前后端代码。目标是先建立一份可审核的学生端数据契约审查材料，把“可用、不可用、契约已有但实现不足、前端展示不合理、需要新增契约”的边界拆清楚。

教师端数据设计采用“学生端数据投影/聚合到教师端”的方向，因此本轮虽然不完整审查教师端页面，但每个学生端字段都需要标注是否可被教师端复用、是否需要班级维度聚合。

## 2. 目标

本轮审查需要产出以下结论：

- 哪些学生端页面字段已经有正式 Client API 契约支撑。
- 哪些字段 OpenAPI 已声明，但 Backend 当前返回空值或聚合不足。
- 哪些字段是前端静态设计、默认假值或历史 Mock，不能作为正式能力。
- 哪些字段需要扩展 Client API、Backend SQL/聚合逻辑或 Agent 输出。
- 哪些能力应降级、删除、延期讨论或重新设计前端交互。
- 哪些学生端数据可以投影给教师端，哪些需要班级维度聚合。

## 3. 非目标

本轮不做以下事情：

- 不直接修改 `../docs/10-client-api/Client-API.openapi.json`。
- 不直接修改前端页面、service 或后端 route。
- 不实现班级 AI 洞察、班级排名、学习动力指数或导出报告。
- 不为页面设计稿中的所有字段强行补 API。
- 不让前端直接调用 Agent Service。
- 不把 Mock 数据或静态示例当作正式字段证据。

## 4. 契约依据

权威来源按以下顺序使用：

1. `../docs/10-client-api/Client-API.openapi.json`
2. `../docs/10-client-api/API_前端接口规范.md`
3. 当前 Backend route/schema/service 实现
4. 当前前端 service 和页面调用
5. Agent Service 已有端点和 schema
6. 页面字段报告、设计稿和 Mock 数据

页面字段报告、设计稿和 Mock 数据只作为“产品设想输入”，不能作为正式契约。

## 5. 审查范围

### 学生端页面

本轮覆盖：

- `StudentProfile`
- `Dashboard`
- `ResourceDetail`
- `LearningPath`
- `Quiz`
- `PracticeResult`
- `AIChat`

### 教师端观察点

教师端不作为第一轮完整审查对象，只做投影依赖标注：

- `TeacherConsole`
- `TeacherStudentReport`

需要特别关注：

- 学生画像能否投影为教师端学生摘要。
- 学习路径状态能否投影为教师端学习进度。
- Quiz 结果和诊断能否投影为教师端薄弱点、练习统计。
- 学习活动是否能聚合为教师端最近活动、重点关注学生。
- 班级洞察是否需要在学生数据稳定后再做 Backend/Agent 聚合设计。

## 6. 审查矩阵格式

每个字段或能力使用统一格式记录：

| 字段 | 说明 |
|------|------|
| 能力名称 | 页面或业务能力名称 |
| 涉及页面 | 使用该字段/能力的前端页面 |
| 当前前端来源 | service 调用、静态内容、Mock、默认值或路由 state |
| OpenAPI 状态 | 已声明 / 未声明 / 部分声明 / 语义不清 |
| Backend 状态 | 已实现有数据 / 已实现但空值 / 聚合不足 / 未实现 |
| Agent 来源 | 不需要 / 已有 Agent 输出 / 需要新增 Agent 输出 / 需确认 |
| 真实数据可用性 | 可用 / 空值 / 不稳定 / 未验证 |
| 假展示风险 | 无 / 默认值兜底 / 静态内容 / Mock 分支 / 契约外字段 |
| 教师端投影 | 不需要 / 可直接复用 / 需聚合 / 需新增字段 / 需重新设计 |
| 建议处理 | 使用固定枚举 |
| 优先级 | P0 / P1 / P2 |
| 待确认问题 | 需要产品、前端、后端或 Agent 共同确认的问题 |

## 7. 建议处理枚举

每项能力只能从以下动作中选择一个主结论，必要时补充次要动作：

- `保留`
- `前端降级`
- `前端删除`
- `补前端消费`
- `补 Backend 聚合`
- `补 Client API 字段`
- `补 Agent 输出`
- `延期讨论`

说明：

- OpenAPI 已声明但 Backend 返回空数组时，优先考虑 `补 Backend 聚合` 或 `补前端消费`，不直接判定为契约缺失。
- 前端使用契约外字段并用默认值伪装成真实数据时，优先考虑 `前端降级`、`前端删除` 或进入 `补 Client API 字段` 候选。
- Agent 能生成但 Client API 未暴露时，应标为 Backend/Client API 设计问题，不允许前端直连 Agent。

## 8. 判断规则

### 明显错误

以下情况可以直接给处理建议：

- 前端读取 OpenAPI 未声明字段，并使用固定默认值展示为真实指标。
- 页面为纯静态内容，但处在正式学习流程入口中。
- Mock 路径或 Mock 字段被真实业务页面依赖。
- 文档已声明字段，但页面注释或逻辑误判为“正式接口未提供”。
- 后端返回字段为空数组，但前端直接隐藏为“无契约”。

### 争议项

以下情况先列证据和待确认问题，不直接强行实现：

- 认知成长曲线是否需要历史快照表。
- 累计学习时长和建议学习时长如何采集。
- 学习动力指数是否有清晰算法和业务价值。
- 班级覆盖率和重点关注学生是否来自规则聚合还是 Agent 总结。
- 资源详情正文是否应来自资源表、文件解析结果还是 Agent 生成内容。

## 9. 第一轮重点关注项

### StudentProfile

重点审查：

- 画像基础字段是否来自 `/profile`。
- 模态偏好、引导粒度、知识坐标、认知盲区是否正确消费正式字段。
- `name`、`level`、`title`、`learning_motivation`、`motivation_percentile`、`weekly_max_accuracy`、`total_duration_hours`、`cognitive_growth` 等契约外字段是否应删除、降级或补契约。
- 雷达图是否使用真实 `modal_preference`，而不是静态数组。
- 认知成长曲线是否有真实时间序列来源。

教师端投影：

- 可投影为教师端学生画像摘要。
- 知识坐标和盲区可用于教师端薄弱点、重点关注学生。
- 动力指数需重新讨论，不作为第一轮默认保留字段。

### Dashboard / ResourceDetail

重点审查：

- `Dashboard` 当前资源列表是否完全基于 `/resources`。
- `ResourceDetail` 是否仍为纯静态页面。
- 资源详情正文、阅读进度、阅读时长、建议用时是否需要新增字段或独立端点。
- 资源类型、章节、知识点、标签、浏览次数是否够支撑资源库主链路。

教师端投影：

- 资源访问和阅读进度可用于教师端学习活动。
- 若没有行为记录表，不应在教师端展示阅读时长或资源偏好分布。

### LearningPath

重点审查：

- `/learning-path` 的 `nodes`、`edges`、`current_position` 是否满足基础路径展示。
- 页面中“欠缺知识点推荐”“关键缺失”“智能体提示”“配套习题”是否存在静态内容。
- 已声明的 `/learning-path/nodes/{node_id}/resources` 是否应接入前端。
- 节点状态枚举和 mastery 语义是否稳定。

教师端投影：

- 路径节点状态可投影为教师端学习进度。
- 节点资源和推荐材料可用于教师端个体诊断，但需要先确保学生端真实接入。

### Quiz / PracticeResult

重点审查：

- `POST /quiz/submit` 返回的 `per_question_results` 是否足够支撑提交后结果页。
- `GET /quiz/result` 是否足够支撑刷新后的结果页。
- `PracticeResult` 是否丢弃了 `diagnosis.summary`、`weak_points`、`suggestions`。
- “历史击败 86% 用户”“新纪录”等是否为静态展示，应删除或补契约。

教师端投影：

- Quiz 统计可投影为教师端练习统计。
- `weak_points` 和诊断建议可投影为教师端薄弱点和行动建议。
- 排名类指标需延期讨论。

### AIChat

重点审查：

- SSE 协议是否已在真实流下验证。
- 会话列表和历史记录是否足够支撑学生端聊天历史。
- Chat 内容是否需要投影到教师端最近活动。
- Token 过期、网络中断、并发消息是否需要前端错误处理加固。

教师端投影：

- 不建议直接投影完整聊天内容。
- 可考虑仅投影摘要级活动，例如“最近使用 AI 答疑次数/时间”，但需隐私和权限确认。

## 10. 输出清单

审查完成后，文档应形成以下清单：

1. 可直接保留的正式字段。
2. 可前端修正的契约误用或假展示。
3. OpenAPI 已有但 Backend 数据为空或聚合不足的字段。
4. 需要新增 Client API 字段或端点的候选项。
5. 需要 Agent 输出或 Agent 聚合参与的候选项。
6. 不建议阶段二立即实现的能力。
7. 可投影到教师端的学生数据字段。
8. 教师端必须等待学生端数据稳定后再做的聚合能力。

## 11. 优先级规则

- `P0`：阻塞真实联调判断，或会让页面把假数据当真数据展示。
- `P1`：阶段二必须处理，影响主要学生端和教师端投影能力。
- `P2`：增强体验、可降级或需产品重新讨论的能力。

第一轮预期：

- `P0` 多数应集中在假展示、静态页面和契约误判。
- `P1` 多数应集中在资源详情、学习路径节点资源、Quiz 诊断、学生画像字段消费。
- `P2` 包括排名、动力指数、导出报告、复杂趋势和系统级指标。

## 12. OpenAPI 更新前置条件

只有满足以下条件后，才进入 OpenAPI 更新：

1. 字段所属页面和业务动作已明确。
2. 数据来源已明确为 Backend SQL、Backend 聚合、Agent 输出或组合来源。
3. 字段类型、空值语义、更新时间和权限边界已明确。
4. 教师端是否复用或聚合该字段已明确。
5. 前端降级方案已明确。
6. 用户确认该能力不应删除或延期。

## 13. 后续流程

推荐流程：

```text
学生端数据契约审查
-> 人工确认字段保留/删除/降级/补契约
-> 更新正式 Client API 草案
-> 审核 OpenAPI 是否漂移
-> 拆分 Backend / Agent / Frontend 实现计划
-> 小步实现与测试
-> 更新 WORKFLOW.md
```

## 14. 验收标准

本轮文档完成后，应能回答：

- 学生端每个关键页面到底依赖哪些正式字段。
- 哪些页面展示当前只是静态或假默认值。
- 哪些字段已经在 OpenAPI 中但后端实现不足。
- 哪些字段需要新增契约，新增前需要什么数据来源。
- 哪些学生端数据可以作为教师端页面投影基础。
- 阶段二下一轮应先改前端、先补后端，还是先更新 OpenAPI。
